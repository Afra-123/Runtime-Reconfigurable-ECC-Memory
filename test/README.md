# Testbench – Runtime-Reconfigurable ECC Memory

This directory contains the simulation and verification environment for the **Runtime-Reconfigurable ECC Memory** Tiny Tapeout project.

The testbench uses **Cocotb and Verilog** to verify the functionality of the memory and its runtime-selectable error-correction modes at RTL.

## Testbench Files

* `tb.v` – Verilog testbench and DUT interface
* `test.py` – Cocotb-based functional tests
* `Makefile` – Simulation configuration
* `requirements.txt` – Python dependencies
* `tb.gtkw` – GTKWave waveform configuration

## What is Verified?

The verification environment checks the major functional blocks of the ECC memory, including:

* Reset operation
* Memory write and read operation
* Runtime ECC mode selection
* 8-bit data storage
* 8-word memory operation
* ECC encoding and decoding
* Error detection and correction
* Parity-only operation
* Hamming-code operation
* SECDED operation
* Detection of double-bit errors in SECDED mode
* Correct recovery of data after a correctable error

## ECC Operating Modes

The memory supports four runtime-selectable modes:

| Mode | Operation |
| ---- | --------- |
| `00` | ECC OFF   |
| `01` | Parity    |
| `10` | Hamming   |
| `11` | SECDED    |

The ECC mode can be changed during operation through the mode-select input. The encoder and decoder operate according to the currently selected mode.

## RTL Simulation

The simulation uses the RTL source specified in the Makefile and runs the Cocotb testbench.

The testbench verifies normal memory operation as well as the different ECC modes. It also checks the behavior of the decoder when errors are introduced into stored codewords.

The generated waveform can be inspected using GTKWave or Surfer.

## Error Detection and Correction

In **Parity mode**, the parity information is used to detect single-bit errors.

In **Hamming mode**, the syndrome generated by the decoder is used to identify and correct a single-bit error.

In **SECDED mode**, the design provides **Single Error Correction and Double Error Detection**. A single-bit error can be corrected, while a double-bit error is detected and flagged.

The runtime-reconfigurable architecture allows the same memory to operate with different levels of error protection without changing the hardware configuration.

## Waveform Output

The simulation can generate waveform output for debugging and verification.

The waveform can be used to observe:

* Clock and reset
* Memory address
* Write enable
* Input data
* ECC mode selection
* Encoded data
* Stored memory contents
* Decoded data
* Error detection status
* Error correction behavior


For a VCD waveform:

```bash

```

### Surfer

The FST waveform can also be viewed using:

```bash
surfer tb.fst
```

## Expected Verification Behavior

During simulation, the ECC memory should:

1. Reset correctly.
2. Accept and store 8-bit input data at the selected memory address.
3. Encode the data according to the selected ECC mode.
4. Read the stored data correctly when no error is present.
5. Operate correctly when the ECC mode is changed at runtime.
6. Detect and/or correct errors according to the selected mode.
7. Correct a single-bit error when operating in a correctable ECC mode.
8. Detect a double-bit error in SECDED mode.
9. Return the correct decoded data after correction of a single-bit error.

## Tiny Tapeout Implementation

The design was implemented and hardened using the **Tiny Tapeout SKY130 digital flow**.

The final submission includes the generated physical-design files, including the hardened GDSII layout and associated timing and layout data.

The design targets a **1×1 Tiny Tapeout tile**.

For complete project information, architecture, RTL implementation, verification details, and physical-design results, see the [main project README](../README.md).
